# 🔧 ПОЛНЫЙ GUIDE: Ошибка "DC_FORBIDDEN: требуется вход администратора"

## Проблема
При открытии админ-панели видишь ошибку:
```
Не удалось загрузить статистику: DC_FORBIDDEN: требуется вход администратора
```

## Причина
Функция `admin_stats()` требует верификацию администратора через ПИН. Если:
- ПИН установлен, но вы его не вводили более 30 минут → доступ блокируется
- ПИН потерян → невозможно войти в админку

## Решение (2 варианта)

### ✅ Вариант 1: БЫСТРЫЙ СБРОС (рекомендуется)

**Шаг 1:** Откройте Supabase Dashboard
- Перейдите на https://app.supabase.com
- Выберите ваш проект

**Шаг 2:** Откройте SQL Editor
- Слева: SQL Editor → New Query

**Шаг 3:** Скопируйте и выполните:

```sql
delete from public.admin_secrets;
delete from public.admin_pin_attempts;
```

**Результат:** Сброшен ПИН и история верификации. Администратор может войти без ПИНа.

---

### ✅ Вариант 2: МЯГКИЙ СБРОС (если хотите сохранить ПИН)

Если вы знаете ПИН и хотите его оставить, просто продлите сессию:

```sql
-- Отметить текущего администратора как верифицированного
-- (замените auth.uid() на ваш user_id, если не знаете его)
insert into public.admin_pin_attempts (user_id, success, attempted_at)
values (auth.uid(), true, now());
```

Это добавит запись о успешной верификации, и доступ будет открыт на 30 минут.

## Если всё ещё не работает

**Шаг 1:** Проверьте, что вы администратор

```sql
-- Выполните в SQL Editor:
select 
  auth.uid() as user_id,
  email,
  raw_app_meta_data ->> 'role' as role
from auth.users
where email = 'ваш-email@example.com';
```

Должна быть строка с `role = 'admin'`

**Шаг 2:** Если нет, назначьте администратора

```sql
-- Замените your-email@example.com на ваш Email
update auth.users
set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb) || '{"role": "admin"}'::jsonb
where email = 'your-email@example.com';
```

Потом **выйдите и снова войдите** в приложение — роль попадёт в JWT токен.

**Шаг 3:** Очистите данные администратора снова

```sql
delete from public.admin_secrets;
delete from public.admin_pin_attempts;
```

## 🛡️ Как это всё устроено

- **admin_secrets:** таблица с хешем ПИНа администратора
- **admin_pin_attempts:** история попыток ввода ПИНа
- **is_admin_verified():** функция, проверяющая:
  - Является ли пользователь администратором (из JWT)
  - Если ПИН не установлен → автоматически верифицирован
  - Если ПИН установлен → требуется успешная верификация за последние 30 минут
- **admin_stats():** функция, требующая верификации перед получением статистики

**Безопасность:** Проверка ПИНа происходит на **уровне базы данных**, пользователь не может её обойти с клиента.

## ✨ Дополнительно

### Установить новый ПИН после сброса

В админке → "⚙️ Настройки" → "Безопасность":
1. Введите 4–12 цифр
2. Нажмите "Установить ПИН"
3. ПИН будет требоваться каждые 30 минут при входе в админку

### Отключить ПИН (сделать админку открытой)

Просто удалите запись из `admin_secrets`:

```sql
delete from public.admin_secrets where id = 1;
```

После этого администратор может входить без ПИНа.
